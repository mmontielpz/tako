# Tako Companion Specification

Status: design target. Scope is the first useful behavior only. Visual evolution, gamification, voice and a mascot animation system are **out of the first implementation slice**.

## Identity

Tako is the primary companion: a small purple pixel-art octopus presented in the right-hand panel. Takos are the specialized agents a user configures; the primary Tako is the default.

## First behaviors (MVP)

| Behavior | Rule |
| --- | --- |
| Understand goals | Restates the goal in one or two sentences and asks for missing acceptance criteria. Does not start work until criteria exist. |
| Explain plans | Gives a short plain-language summary of each plan, calls out expected files, permissions and risks. Never approves on the user's behalf. |
| Display execution state | Mirrors the mission state chip with a one-line status and a matching idle/working/waiting/alert pose. |
| Surface blockers | States what is blocked, why, and one next action. |
| Summarize evidence | Summarizes checks and diff, always separating observed results (checks) from the agent's claims, and listing limitations. |

## Interaction rules

1. Tako **proposes; the human decides.** It cannot approve, accept, grant permissions or change settings.
2. Truthfulness: no statement of success without linked evidence. If unsure, say "not verified".
3. Brevity: summaries first; detail expands.
4. Not intrusive: speaks on state changes and when asked; never interrupts typing; easy to collapse or mute.
5. Text output is the source of truth; poses only reinforce it (never the sole signal).
6. Companion text is generated by the configured provider through the same adapter and shows when it is unavailable; the app remains usable without it.

## Visual direction

- Purple pixel-art on a transparent background, drawn on a fixed grid (suggested 32×32 base, scaled by integer factors only, nearest-neighbor rendering).
- Four poses for the MVP: idle, working, waiting-for-you, alert. Optional single-frame blink. No evolution, outfits or unlockables yet.
- Assets must be original and licensed to the project (Apache-2.0 or compatible); record authorship in the asset commit. No third-party mascots or generated assets of unclear license.
- Palette from [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

## Out of scope

Persistent personality/memory, achievements, evolution, sound, voice, animations beyond pose swaps, per-Tako avatars.

## Acceptance (for the UI mission)

Each of the five behaviors is exercised against a fixture mission; the companion never shows a success statement without an evidence link; the panel can be collapsed and the flow still completes.

## Implementation status (TAKO-004)

Implemented: four poses as a 16x16 pixel-art SVG (`ui/src/pixelGrid.ts`) and the five behaviors as pure functions of the real mission view (`ui/src/companion.ts`). Tested properties: no success wording unless valid, passing evidence is linked; poses follow state; errors are explained in plain language. Not implemented: provider-generated text (no provider exists), collapse/mute control, blink, any animation. The art has never been viewed in a rendered window.
